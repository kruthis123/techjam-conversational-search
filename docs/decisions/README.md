# Architecture Decision Records

During ARCHITECTING, use `docs/templates/SYSTEM_DESIGN_RECORD.md` and sequential IDs such as `SDR-001`. These records capture the user's understanding of representations, capability alternatives, trade-offs, experiments, and conceptual synthesis. They are not implementation ADRs and need not force a premature choice when evidence is missing.

If the user later chooses to implement, translate only the relevant system-level choices into focused ADRs using `docs/templates/ADR.md`. Do not treat an exploratory SDR as implementation approval.
